Maintenance release / corporate deployment

Trier OS is feature complete and feature frozen. Deploy one corporate HQ instance holding authoritative plant databases. Plants connect to HQ; optional local hub/cache fallback needs deployment-specific routing/recovery validation. The default Electron package starts an embedded full server on its host, not an automatically configured HQ thin client.

Production requires independent strong JWT_SECRET and HUB_TOKEN_SECRET, NODE_ENV=production, DISABLE_LIVE_STUDIO=true, trusted TLS, account review and secured consistent backups. Windows packages bundle the existing OpenSSL certificate-generation prerequisite with its separate Apache-2.0 notice; each installation generates its own key/certificate. A generated self-signed certificate still requires client trust or replacement with an operator-provisioned trusted certificate. Provision 64+ random hex characters for session/hub secrets; startup checks reject missing/short/recognized placeholders rather than proving entropy. Do not replace real operational data with bundled demo databases during an upgrade.

Public demo accounts are deliberately confined to examples and can be seeded in production. Ghost test accounts are a separate non-production seeding class; switching mode does not remove existing accounts. Browser sessions use an HttpOnly cookie with 7-day absolute expiry; the React UI separately applies a 15-minute inactivity timer/client logout. The localStorage hub token is separate and expires after 24 hours. Logout clears the cookie without revoking a copied token.

If using HA, explicitly provision a fresh 64-character hex secret on paired corporate servers, through authenticated HA configuration or protected HA_SYNC_KEY environment. Environment takes precedence over the local resolved-data .sync_key file. Missing/invalid/retired provisioning denies peer auth. Rotate any historically distributed credential, including older portable ZIP copies. Never copy a shipped historical key.

Floorplans accept validated PNG/JPEG/GIF/WebP; convert SVG to a safe raster before upload. Active/unknown historical attachments download with execution-protection headers. Complete browser regression and later targeted validation are distinct from physical outage/restart and paired-server recovery, which are not fully validated.

Method C — ZIP Portable

No installer needed  ·  Run from any folder or USB drive  ·  ~5 minutes

💡
What "portable" means

Nothing gets installed on your computer. Trier OS runs directly from whatever folder you unzip it into. Move the folder to a USB drive and it runs from there too. Delete the folder to remove it completely — no uninstaller needed.

ZIP first run: provision this installation's private secrets before launching

The release contains a blank .env.example, not shared session secrets or host TLS keys. Open Windows PowerShell in the extracted folder and run:

if (Test-Path -LiteralPath '.env') { throw 'Existing configuration: review it instead of replacing secrets.' }
$installRandom = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$installJwtBytes = New-Object byte[] 32
$installHubBytes = New-Object byte[] 32
$installRandom.GetBytes($installJwtBytes)
$installRandom.GetBytes($installHubBytes)
$installJwtValue = ($installJwtBytes | ForEach-Object { $_.ToString('x2') }) -join ''
$installHubValue = ($installHubBytes | ForEach-Object { $_.ToString('x2') }) -join ''
@("JWT_SECRET=$installJwtValue", "HUB_TOKEN_SECRET=$installHubValue", 'PORT=3000', 'NODE_ENV=production', 'DISABLE_LIVE_STUDIO=true', 'ALLOWED_ORIGINS=http://localhost:3000') | Set-Content -LiteralPath '.env' -Encoding ASCII
$installRandom.Dispose()

Restrict access to the resulting .env; never publish it. Then start Trier OS.bat. Existing installations retain their own protected configuration; do not replace it during an upgrade. HA needs separate explicit peer provisioning. The first HTTPS certificate must be trusted on clients.

1

Unzip the file

Find TrierOS-Setup-3.7.2.zip in your Downloads folder. Right-click it and choose Extract All.

Choose a destination folder — for example C:\TrierOS\ or a folder on a USB drive. Click Extract.

2

Open the extracted folder

Navigate into the folder that was created. You should see Trier OS.bat, server/, seed-data/, and runtime/. The launcher initializes retained storage once; packaged seeds do not replace an existing live database.

3

Launch Trier OS

Double-click Trier OS.bat to launch. A console window will open showing the server log — leave it running. On first launch, a text file with your login credentials will open automatically in Notepad.

Once running, open your browser on this machine and go to http://localhost:3000.

Configure certificate trust on the device; dismissing a development warning does not guarantee camera access in every browser. Your server's IP address is shown in the console window.

Moving an initialized deployment requires preserving its storage locator and access permissions.

What You'll Need First

🟢
Node.js v22+

The runtime that powers Trier OS. Download from nodejs.org — get the LTS version.

Free — nodejs.org
🐙
Git

Used to download the code from GitHub.

Free — git-scm.com
🔍
Already have Node.js?

Open a terminal and run node --version. If you see v22 or higher, skip the Node.js install below.

1

Install Node.js (if needed)

Go to nodejs.org, click the big green LTS button, and run the installer. Accept all defaults. Make sure "Add to PATH" is checked.

Verify it worked:

$ node --version # Should show v22.x.x or higher
2

Install Git (if needed)

Go to git-scm.com/downloads, download for your OS, and run the installer with all defaults.

$ git --version # Should show git version 2.x.x
3

Download Trier OS

Open a terminal, navigate to where you want to put Trier OS, and run:

$ git clone https://github.com/DougTrier/trier-os.git trier-os $ cd trier-os
4

Install dependencies

This downloads all required packages. Takes 2–5 minutes.

$ npm install

Review errors and security-relevant warnings; do not dismiss them based on color.

5

Set up configuration

Windows:

$ copy .env.example .env

Mac / Linux:

$ cp .env.example .env

The defaults in .env work out of the box for development. Trier OS auto-generates security keys on first boot.

6

Review installed demonstration data

Existing application startup/provisioning initializes the databases. Available demo records depend on the distribution. The exported seeder module is not a database-seeding CLI.

7

Start Trier OS

$ npm run dev:full

Wait for both of these lines to appear:

API | API listening on its configured port (normally 1937; HTTPS 1938) UI | Local: http://localhost:5173/

Then open your browser and go to http://localhost:5173.

💡
Keep the terminal open.

Trier OS runs as long as this terminal is open. Press Ctrl + C to stop. Run npm run dev:full again to restart.

📱
Testing scan from a phone, tablet, or Zebra scanner?

Use https://YOUR-SERVER-IP:1938 — not port 5173. Mobile browsers block camera access on plain HTTP. Configure certificate trust on the device; dismissing a development warning does not guarantee camera access in every browser. Your server IP is shown in the terminal output when Trier OS starts.

📱
Plant floor devices (phones, tablets, Zebra scanners) need HTTPS to scan.

Open https://YOUR-SERVER-IP:1938 on any device that needs to use the barcode or camera scan features. Plain HTTP blocks camera access in mobile browsers. Use a certificate trusted by the device; self-signed development certificates may need explicit trust setup.

1

Find your credentials

On first launch, Trier OS automatically generates a secure password for the creator account and saves it to a file called first_login.txt.

EXE / MSI: The file opens automatically in Notepad when the app starts for the first time.

ZIP / Portable: The file opens automatically in Notepad when the server starts for the first time.

From Source: Look for data/first_login.txt in your project folder.

⚠️
Save this password before closing the file.

Protect it, change your password and securely remove the file. Do not delete the auth database to reset a password: that destroys identities and role assignments. Use an existing authorized administrator and a planned backup/recovery procedure.

Log in as creator

On the login screen, enter:

Upgrading an Existing Installation

Normal updates and reinstalls preserve existing data.
  1. Arrange a maintenance window. Exit Trier OS from the tray and stop its server/service; confirm clients are disconnected.
  2. Keep a verified backup of all databases, uploads and private configuration. The installer also verifies a recovery copy before updating. New machine installations retain storage under %ProgramData%\TrierOS; portable storage is under %LOCALAPPDATA%\TrierOS\portable. The deployment locator identifies the actual directory, including a configured external DATA_DIR.
  3. Use the same installer format and intended installation path. Existing installations follow Update Existing Installation: program files are updated and initialized data is reused. Legacy install-relative data is adopted before program cleanup. Do not manually replace live databases with seed files.
  4. Preserve your installation-specific session secrets and operator-provisioned trusted TLS. Do not restore a historically shipped HA credential or shared package TLS key. Provision a fresh HA secret on both peers; generate or provision installation-specific TLS if needed.
  5. Start Trier OS and verify the About version, accounts, plant selection, representative records and a normal scan. Check backups and any HA/offline deployment separately.
  6. If validation fails, stop the application and restore the prior application and matching full data/configuration backup together. Do not reset the auth database or overwrite live data while the server is running.
  7. Ordinary uninstall retains data, accounts, password hashes, roles, groups, memberships and grants. Reinstall detects retained storage. Destructive reset is a separate explicitly confirmed operation, with a verified backup; it is never the normal update or uninstall path.

Useful Commands (From-Source Only)

Start the app (run this every time)
$ npm run dev:full
Production mode — Windows cmd only; protected secrets must be provisioned first
$ npm run start:prod
Authorized update only — preserve local work, back up consistent data and validate separately first
$ git pull origin main && npm install

Do not use the seeder module as a demo reset CLI. Use the existing authorized location/data workflow after confirming the dataset is disposable and backed up.

Linux/macOS production source service: NODE_ENV=production DISABLE_LIVE_STUDIO=true npm run start:cluster. PowerShell: set $env:NODE_ENV = 'production' and $env:DISABLE_LIVE_STUDIO = 'true', then npm run start:cluster.

Troubleshooting

Common Issues

?

Windows SmartScreen blocked the installer

Click More info on the SmartScreen dialog, then click Run anyway. Unsigned installers can trigger this warning. Verify the release source and SHA-256 checksum before deciding to proceed; open-source licensing alone is not proof of installer safety.

?

Login fails — "Invalid credentials"

For a fresh creator account, use the private password from first_login.txt; after changing it, use your new password. If the file did not open automatically, look for it in the data/ folder inside your install directory. Use the exact configured username; passwords are case-sensitive.

?

App opens but shows a blank or loading screen

Wait 15–20 seconds on first launch — the database is being initialized. Refresh the page. If it persists, try closing and reopening the app.

?

"Port already in use" error (From Source only)

Check the configured listener: normally API 1937/1938, development UI 5173 or portable HTTP 3000. Identify the owning process before stopping anything. Coordinate any port change with client/proxy configuration.

?

npm install fails (From Source only)

Confirm Node.js v22+ is installed: node --version. Delete the node_modules folder and run npm install again. Make sure you have an active internet connection.
